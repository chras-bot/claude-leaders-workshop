# Contributing

This repository is a shared workspace for one workshop exercise. These are the same rules the agent follows, written for people.

1. Fork the repository and clone your fork.
2. Pick a short alias in lowercase letters, digits, and hyphens. Do not use your name, your employer, a client, or your GitHub username. End it with two digits, such as `ops-lead-47`. Create a branch named `submission/<alias>`.
3. Add one folder, `submissions/<alias>/`, with two files:
   - `rules.md`: 15 lines or fewer, counting the numbered rules and the four labeled lines, that tell an agent how to do one task your team repeats.
   - `checks.md`: 3 pass or fail checks and 1 trap, a case where a fluent answer looks right but is wrong.
   Start from `templates/`. See `examples/` for the shape.
4. Do not change any file outside your folder.
5. Remove anything private before you commit. That means names of people, clients, or employers, emails, phone numbers, URLs, handles, internal system names, ticket keys, money figures tied to a company, and any secret. Use roles and generic terms instead.
6. Commit with a plain imperative message, such as "Add rules and checks for weekly access review."
7. Push to your fork and open a pull request to this repository. Use the pull request template and keep `@chanceypraecipio please review` in the description.

The repository is public. Anything you commit can be read by anyone.

By opening a pull request you agree your files are shared under the MIT License.
